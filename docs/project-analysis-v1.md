# Retained package reader: proposed interpretation, existing estimate

This local implementation connects the retained project library to the configured OpenAI reader and the existing painting estimate. No hosted schema, allowance, resource or record was changed. Controlled provider-contract tests use the real installed SDK with an explicit controlled SDK fetch dependency returning synthetic HTTP Response objects without sending a provider HTTP request; they establish the connection and safeguards, not real-model interpretation accuracy.

## Production path and minimum prerequisites

`/api/projects/[projectId]/analysis` verifies the existing owner session, then uses `SupabaseProjectLibraryStore`, `SupabaseProjectAnalysisStore` and `createProjectAnalysisProvider()`. Browser fields and environment flags cannot choose a local/synthetic store, another model or arbitrary source URLs. Source text/images are retrieved by exact retained file/version/hash/page identities on the server. The provider uses the existing `STUDY_MODEL` (`gpt-6.1-sol` at this checkpoint), existing server-only `OPENAI_API_KEY`, Responses JSON schema, zero retries, 60-second SDK timeout, `store: false`, no tools and a 6,000-output-token cap. Temperature is not added.

Hosted execution requires separate approval and verification of:

1. The normalized/paginated project-library definitions and private Storage setup in `project-library-v1.sql`/`project-library-v1.md`.
2. The **review-only, unapplied** `database/project-analysis-v1.sql` attempt ledger, service-role-only functions and shared reservation trigger. No allowance row, maximum, entitlement or default capacity is created by that file.
3. The existing independently administered owner-level `plan_study_allowances` row with sufficient remaining attempts/input/output capacity. Closed or absent capacity rejects a new attempt before provider invocation. This task does not authorize changing it.
4. Actual Auth/RLS, RPC/trigger behavior, deployed resource/font/worker packaging, storage/network limits and capacity testing in an authorized environment. Source/query-shape checks do not establish database execution or hosted portability.

The shared trigger checks reservation increases under the existing locked allowance row against **both** legacy Study and project-analysis running/unknown ledgers. It does not rewrite either provider, alter maxima or touch Estimate usage. Its intentional effect is owner-wide exclusion while another attempt/reservation is outstanding. Settlement decreases remain available. Unknown or expired outcomes retain reservations until separately authorized reconciliation. This definition is inactive until approved/applied; the old configured Study allowance is not a new automatic grant to this feature.

## Bounded source packets and provenance

An explicit analysis request selects one to four target physical pages/photos and up to eight context pages. It sends identities only. The server retrieves individual prepared text pages on demand, avoiding whole-package text in discovery responses. It includes up to four actual page/photo images, prioritized by selected target/context role, with an explicit per-source record when an image was not supplied. Context can cross-reference plans, specifications, schedules, notes and addenda; context use is not independent review of every context image or the entire package.

Visual preparation shares the existing project decoder queue and owner-wide lease. The lease/queue are released before the provider reservation/call. A batch checks a 45-second preparation budget between sources; native decoder termination and hosted timeout behavior remain unverified. JPEG/PNG originals use the retained 60 MP-safe processing function and a JPEG copy up to 1,600 pixels on the long side. PDF pages reuse the existing strict retained renderer and its supported codecs, content limits, local fonts and **3 MiB original PDF bound**. Larger PDF text can still be used when prepared; the unavailable page image is recorded as a limitation. No remote fonts, browser URLs, OCR dependency or photo-derived measurement is substituted.

The text/context JSON is at most 120 KB; image bytes at most 8 MiB. Exceeding a batch/text bound fails explicitly; content is not silently truncated. Unavailable text, unsupported visual preparation, empty/scanned content and unprovided images remain on the exact source record. A usable remainder can yield a limited result; if no target has readable text or a supported image, no provider call occurs.

Each immutable attempt records the target/context roles, original identities, text hashes/status, actual delivered image hashes/status and per-source issues. Results retain field-level citations, exact quotations or normalized image regions, distinct requirements/assumptions/questions/conflicts/boundaries/observations, explicit finding/work relationships and typed proposed takeoff inputs. IDs are prefixed by the durable attempt identity; the result identity binds the packet and result. The public parser checks strict shape, relationships and bindings, not the truth/completeness of model reasoning.

The outgoing instructions treat all package content as untrusted data. Conflicts require incompatible requirements for the same work, location and conditions. Complementary general/specific wording, unknown finish extent, different rooms and different conditions do not automatically become conflicts. Missing references never acquire invented contents. Photos can support visible conditions and tentative clues, while measured dimensions, room identities and repair areas remain unavailable without source-backed evidence.

## Results, retries and existing estimate authority

The packet fingerprint binds ordered target/context identities, prepared text hashes and extraction states, configured model and explicit instruction/rendering recipes. A completed/running/unknown identical packet reopens its durable record before downloading/decoding images or making another provider request. New attempts require an atomic allowance claim with the same conservative reservation as retained Study review: 200,000 input tokens and 6,000 output tokens. Concurrent clicks cannot claim a second attempt for the same packet. Known failed responses require an explicit retry and allow at most two attempts per fingerprint. Unknown outcomes are never automatically retried, including with another click/key.

Known usage settles once. Transport or missing-usage uncertainty retains the reservation. Result/source validation failures publish no findings. A source replacement during the call prevents publishing current findings while preserving the historical attempt and known usage. Completion persistence is outside the provider-error catch and is not repeated after an ambiguous write. Read-only history/reopening remains available when an allowance is closed. The separate `GET ...?analysisId=...&verifyCurrent=1` gate verifies every recorded target/context dependency, including uncited or failed/empty prepared text, before new saves/exports. Historical reads do not require current originals and never acquire a reservation.

The reader outputs **inputs, not arithmetic or prices**. Every number must have a cited printed value and compatible unit. Numeric observation guesses, photo-derived quantities, absent room/location wording, uncited images, stale identities, unsupported fields and broken relationships fail validation. Printed visual annotations remain model transcriptions requiring review, not calibrated measurement. Structural evidence checks cannot prove semantic correctness.

The existing deterministic painting tools calculate supported quantities, exact approved pricing profiles supply costs, and the existing draft/proposal system preserves separate quantity/cost approval, saved revisions, source freshness and customer-safe PDFs. Source requirements, assumptions and unanswered decisions do not auto-approve work. No model total or alternate pricing engine is introduced. Unresolved measurements, responsibility, finish extent and incompatible conditions/rates remain decisions. A successful model response does not establish complete package coverage or contractor approval.
